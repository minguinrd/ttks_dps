# Branding + Display Language Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admin-editable branding (site name, logo, accent color) plus per-user English/Spanish display language covering every visible string.

**Architecture:** A `settings` key-value table feeds a context processor that restyles `base.html` (title, navbar brand, accent CSS variable) and serves an uploaded logo from `DATA_DIR` via a public route. A hand-rolled i18n module (`app/i18n.py`, `_()` helper, `es.json` catalog) resolves locale per request from `users.language`, is injected into Jinja and Python, and is applied by a full template/flash sweep guarded by a completeness test; notifications gain `message_key`/`params` so they render in each reader's language.

**Tech Stack:** Flask + Flask-SQLAlchemy + Flask-WTF + Alembic + pytest; JSON catalogs; zero new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-11-branding-i18n-design.md` (binding authority).

## Global Constraints

- **No new dependencies.**
- **State-changing routes: POST + CSRF**; branding routes `role_required("admin")`; the logo service route is public (login page needs it).
- **Logo:** stored only in `DATA_DIR/branding/` (Docker volume, never the image tree); server-generated filename (`logo.<ext>`), extension whitelist `.png .jpg .jpeg .svg`, ≤ 2 MB; incoming filename never used as the stored path.
- **Accent color** validated `^#[0-9a-fA-F]{6}$` on write AND sanitized on read (a stored value failing the pattern renders the default `#0d6efd`, never raw markup).
- **i18n:** `SUPPORTED = ("en", "es")`; catalog `app/locales/es.json` (flat, literal keys → Spanish); no `en.json` — `_()` falls back to the source string; translation keys are always literals (never f-strings); translate-then-format for parameterized strings.
- **User-generated content never translated:** ticket subjects/comments/descriptions, names, department names.
- **Anonymous pages stay English** (login/register/pending): locale is `en` when unauthenticated.
- **Migrations:** chain on the current Alembic head via `flask db migrate`; review the generated file for add/drop only; do not regress the `migrations/env.py` `PRAGMA foreign_keys=OFF` fix.
- **Existing tests stay green:** English source strings and the legacy `notifications.message` writes are unchanged, so current assertions hold. Baseline: **134 passed** at `f2d7aab` + this plan's docs commits.
- Every task ends green: `.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/pytest -q`; pytest `pythonpath = ["."]`; ruff excludes `docs/`; Python 3.15.

## Review Focus

Failure modes the spec implies but no single happy-path test pins — each gets its test in the owning task:

1. **Stored accent-color injection:** a `settings` row poisoned with `#fff;</style><script>...` (written before validation existed, or via DB) must render the default, not execute — owned by Task 1, test `test_accent_color_sanitized_on_render`.
2. **Upload abuse:** an incoming filename like `../../evil.php` or an oversized/wrong-type file must never land outside `DATA_DIR/branding/` or with a non-whitelisted extension — owned by Task 2, test `test_logo_upload_rejects_bad_type` (cases: `.php`, `../`-style name, > 2 MB).
3. **Dynamic keys escaping the catalog:** an f-string or concatenated `_(...)` call would never match `es.json` and silently leak English — owned by Task 5, test `test_no_dynamic_translation_keys` (scan fails on `_(f"`, `_(" +`, `_(f'`).
4. **Notification formatting with hostile/user data:** `_(key).format(**params)` where a param value contains braces (a username like `{oops}`) must render, not raise — owned by Task 4, test `test_notification_params_with_braces_render`.
5. **Completeness drift:** any marked string missing from `es.json`, or stale catalog keys, must fail the build — owned by Task 5, test `test_all_marked_strings_translated` (bidirectional scan of templates + Python).

**Interfaces:**
- Consumes: conftest `app`, `client`, `user_factory`, `login`.
- Produces (Tasks 4-5 rely on these exact names):

  - Catalog loader: lazily reads `app/locales/es.json` once per process (module cache), `{}` if file missing
  - `g.locale` set by `before_request`: `current_user.language if authenticated and in SUPPORTED else "en"`

  - Route `main.language_save` `POST /profile/language` (login required, CSRF, flash + redirect to profile)
